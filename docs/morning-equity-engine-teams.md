# Morning PAPER test with independent equity Grok teams

Prepare with the pinned `install-paper-day-trial.ps1 -ExperimentProfile
CENT_EXECUTABLE_V3 -RecordedSession <closed prior recording> -EngineTeams`.
The installer retains its reviewed frozen blocker comparison, Windows tests,
backup branch and fast-forward-only update. It never starts Atlas, makes an API
request, edits `.env`, or creates an experiment deadline during preparation.
A Grok key/model must already be configured locally; preparation checks presence
and model format without claiming online validity.

The operator launches the printed `Start-Atlas-Paper-Trial.ps1` tomorrow and
clicks START in the normal visible GUI. The eight-hour trial begins on first
manual launch. Restarts reuse its expiry and consumed native entry budget.
Native V3 Momentum/Scalper paper entries retain their current setup, fresh quote,
account, ownership and risk checks. Limits remain ten shares/$100 per position,
$1 modeled initial risk, fifty shared entry attempts and $5,000 entry notional.
Stops, targets and protective exits remain native; paper fills are not guaranteed.
Crypto NFI is not connected by this launch and its earlier historical result
is not an equity strategy qualification. Existing crypto trials remain separate.

In a second shell, manually launch `Start-Grok-Teams.ps1`. This is an explicit
paid research process, not an executing controller. Each engine has its own
analyst and coordinator client state. The coordinator receives the original
same-engine evidence and its analyst's response. No recommendation from one
engine becomes authority for the other. Original native results are withheld.
The process reads the exact trial-bound recording; it never invokes native
callbacks, a broker, a simulated order service or a position manager.

Both lanes run concurrently. A separate NEWS/SCOUT desk collects cited public
Web/X research about observed equity symbols and creates a watchlist. Only
cited, unexpired research completed before the captured event can be attached.
Missing or failed news is explicitly omitted, never awaited by an engine.
News is not a verified catalyst, executable quote or proof of profitability.
The desk gathers only up to 24 observed symbols, not the whole market.

The SQLite request budget persists across restarts and processes: at most sixty
reserved attempts in this trial, counting failures and unknown completions.
Each equity team can use twenty calls (ten two-stage cases), and NEWS/SCOUT can
use twenty calls total (ten cycles). Engine sampling has a nominal hourly cadence.
The independent news desk refreshes after 55 minutes initially and hourly
thereafter, ahead of later nominal engine samples. Source TTL and pre-event
availability are still checked. This is sampled collaboration research, not
continuous review of every signal or all 23 historical setup families. Provider search turns are
also bounded; an attempt cap is not a fixed dollar cost. Engine model transport
uses the existing 256-output-token/low-reasoning profile where supported. Native
trading never waits for these requests. Records compare completion age against
2 seconds for Scalper and 10 seconds for Momentum; these timing labels confer
no execution authority. Provider latency can still exceed either budget.

Capture retains the existing 4-GiB/eight-million-event daily journal, setup and
stream assessments, provider times and book data actually supplied, native
orders/fills/exits and local learning outcomes. Capacity limits or queue loss
invalidate complete evidence. Context sampling remains separately capped at
10,000 fresh records/64 MiB. Unsubscribed symbols and missing history, depth or
news are not captured. Nothing enables additional repository strategies.

`grok-team-budget.sqlite3` retains role contexts, responses, failed reservations
and latency. Each observer invocation writes a new `grok-team-observer/run-*`
directory with paired private proposals and a summary. BUY/PASS/EXIT opinions
are not fills; no Grok PnL or win rate is calculated. No hypothetical fills are
backdated. Provider bodies, credentials and exception strings are not logged.
`Show-Morning-Status.ps1` prints a small read-only trial/recording/engine/call
report. Keep the underlying private trial and daily session directories.

`Pause-New-Entries.ps1` pauses native admission. `Stop-Grok.ps1` stops new model
work. Keep Atlas running while native positions need protection; close it
normally when done to finalize capture. The observer notices the closed recording
and stops independently. Do not run old intentions or execution launchers beside
this observer. Options, futures and NFI execution are not added by this test.

`tools/update-morning-team-budget.ps1` upgrades an already prepared team trial
without recreating it: it preserves experiment expiry, native entry attempts,
existing model call rows and `.env`. Close Atlas and Grok normally first.
Unused allowance is not a deadline extension. Eight hours still starts at the
original manual Atlas launch; restarting either process does not renew it.

The hourly case slots are now stored in the same SQLite ledger and anchored to
the original experiment start. Restarts cannot spend another case in a sampled
engine hour or reset the news refresh slot. Eight engine hours use at most sixteen
calls per engine; nine news slots (initial, +55 minutes, then hourly) use at most
eighteen calls. Each group fits its twenty-attempt allowance without needing an
intra-day refill. Failed requests consume their slot and are not retried. No
request-count-based observer shutdown occurs before the eight-hour deadline.

This does not remove the native fifty-entry/$5,000-notional trial allowance or
account, risk, quote and capture-health checks. Those can pause new paper entries
before the deadline; protection and observation continue independently. Raw
recording still has finite capacity, and queue/disk failure cannot be promised
away. The compact status report shows remaining native entry attempts, remaining
trial hours and remaining calls for each research team. Do not interpret a running
observer as proof that native admission or complete data capture remains healthy.

When the append-only context sample reaches its 10,000-record/64-MiB bound, an
independent bounded latest-context cache continues publishing one atomic file
per equity engine. This uses the existing context writer, coalesces updates, and
adds no native provider request or model call. Team sampling validates source,
owner, baseline and original quote age before consuming it. The cache is current
state, not a replacement for the durable raw journal or a complete history.
It prevents context-sample exhaustion from starving a later hourly Grok slot.
