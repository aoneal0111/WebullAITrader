# Persistent Atlas paper operation

This is an explicitly selected persistent PAPER operating mode, separate from the existing time-limited research trials. Live orders remain disabled. It keeps the same GROK_WARRIOR_ACCOUNT_V6 strategy settings, native account sizing, cent targets, setup parameters, clock tolerance, partial exits and stop-management policy. It does not tune indicators or assert profitability.

The operator manually starts Atlas using Start-Atlas-Paper.ps1 and clicks START. The new operation has no trial expiry, entry-attempt quota, extra trial share/notional/risk limit, total recording byte/record quota, durable Warrior paid-call quota or 120-request client cutoff. Stopping Atlas and reopening the same launcher reuses the operating identity and accounting ledgers. Previous trials are preserved rather than rewritten or extended. Crypto continues independently and is visible in Atlas's Crypto tab.

Grok controls Warrior; Scalper remains native. The independent Director no longer samples four symbols once per three hours. It cycles through the entire fresh, subscribed, eligible watchlist in oldest-presented order. Each request contains up to four symbols, at least ten seconds separate batches, and a given symbol is ordinarily presented at most once per minute. These are request pacing and payload constraints, not a lifetime quota or a four-symbol universe. Native setup-triggered reviews remain a separate concurrent lane. The same client has two concurrent request slots; actual provider 429 Retry-After backoff is retained. No paid request is retried into an order decision.

Watchlist coverage reports symbols presented, timestamps, fresh symbols not yet presented, and input refusals for stale/ineligible context or missing completed bars. A symbol supplied in a prompt is not proof of a model action or an order. Unsubscribed exchange symbols and absent current-session bars are not invented. Higher cadence increases paid API usage; transport attempts and token usage remain visible with no artificial paid-call quota.

Normal market/account/execution conditions still apply: tradable unhalted instruments, current quotes and account context, available buying power, configured account risk, canonical order ownership and protective exits. The operator PAUSE_ENTRIES and STOP_GROK markers remain supported. These are paper execution controls, not research quotas. A model can PASS. Missing data, provider failures, queue loss or disk failure are surfaced and may pause new entries; they are not disguised as successful trading. Protective SELL handling remains independent.

Capture continues in rotating segment files without deletion or a fixed total quota, so disk usage grows. The transport ledger also grows. Existing bounded full-history research exporters may need compact or segmented review for large recordings. The preparation script neither launches Atlas nor restarts any crypto container; it runs offline regression checks first. No external Webull or xAI connectivity or future uninterrupted runtime is attested by those checks.
