# Continuous PAPER account-read recovery

The November 13 workstation diagnostic reports a NetworkError-triggered runtime shutdown at 14:43:38 UTC after repeated stream reconnect failures. It also reports three successful reconnects and a last normalized event at 14:42:54 UTC. Cleanup for this incident completed; an earlier pasted report-worker timeout is a separate event. The compact diagnostic does not contain the original account-poll stack or underlying SDK failure, so an external provider/network root cause is not attested.

A reproducible fatal path remained: account reads retried only twice and raised the third retryable NetworkError even in persistent PAPER operation. A fixture that recovers on its ninth read now survives with interruptible 1/2/4/8/16/30-second capped backoff. Only the explicit NATIVE_PAPER_OPERATION_V1 scope in PAPER gets continued retries. Legacy trials keep three attempts; LIVE behavior and authentication, validation and nonretryable failures remain unchanged. No order mutation is retried.

During this recovery, ACCOUNT_DATA_UNAVAILABLE pauses new entries through the existing paper qualification policy. An account-recovery-status.json file exposes state, attempt count and sanitized failure identity. No snapshot or timestamp is synthesized. The marker is cleared only after a real account snapshot has been accepted by the normal publication sink. A failed sink cannot clear it. Stream reconnect success cannot override an account-data pause. Existing position protection remains available whenever its genuine market inputs are available.

Driver construction for the persistent operating mode starts with account data unavailable, preventing a previous process's account state from being treated as new. The first failure is recorded before cleanup begins; deliberate consumer teardown is no longer labeled an additional unexpected exit. More specific account failure codes are recorded without credentials, response bodies or raw SDK messages.

The repair script preserves the existing operating identity, launchers, strategy settings, ledgers and crypto containers. It does not start Atlas or call Webull. Regression checks validate the recovery policy, not external connectivity. Continued DEGRADED status is honest when an outage persists; this patch cannot guarantee provider recovery. The earlier report-worker timeout remains independently diagnosable.
